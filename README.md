# music-manager

YouTube URL을 입력하면 오디오를 M4A로 내려받고, 썸네일을 JPEG로 만든 뒤, `Artist` / `Title` / `Album` 메타데이터와 앨범 아트를 M4A에 기록하고 결과를 검증하는 macOS용 도구입니다. 데스크톱 앱(`Music Manager.app`)과 터미널 CLI(`music_manager.py`) 두 가지로 쓸 수 있습니다.

## 설치

외부 도구는 Homebrew와 pip로 설치합니다.

```bash
brew install ffmpeg exiftool
python3 -m pip install -U "yt-dlp[default]"
```

- CLI는 표준 라이브러리만 사용합니다. Python 3.9 이상이면 됩니다.
- GUI는 PySide6가 필요합니다. 빌드된 `.app`을 실행하는 경우에는 따로 설치할 필요가 없습니다.

## 앱 사용법 (GUI)

1. 위의 [설치](#설치)를 마칩니다.
2. `Music Manager.app`을 실행합니다.
3. URL을 입력하고 **URL 추가**(Enter)를 누릅니다. 여러 개는 **붙여넣기**로 한 번에 넣을 수 있습니다.
4. **다운로드 시작**을 누르면 순서대로 처리합니다. 한 곡이 실패해도 다음 곡을 계속합니다.
5. 목록에서 항목을 고르면 상세 정보(Artist, Title, Album, 썸네일, 결과)를 볼 수 있습니다.

### 목록에서 할 수 있는 일

| 기능 | 설명 |
|---|---|
| 중복 확인 | 같은 영상은 URL 형식이 달라도 한 번만 들어갑니다. |
| 제목 조회 | URL을 추가하면 영상 제목을 가져와 목록에 표시합니다. |
| 진행률 | 오디오 다운로드 단계만 실제 진행률을 보여 줍니다. 나머지 단계는 현재 단계 이름만 표시합니다. |
| 선택 삭제 | 실행 중이 아닐 때 선택한 항목을 목록에서 지웁니다. **저장된 파일은 지우지 않습니다.** 완료, 실패, 취소, 건너뜀 항목 모두 지울 수 있습니다. |
| 선택 다시 시작 | 실패, 취소, 건너뜀 항목을 대기열에 되돌려 바로 시작합니다. 완료된 항목은 대상이 아닙니다. |
| 취소 | 실행 중인 다운로드를 멈춥니다. 진행 중인 yt-dlp와 FFmpeg 프로세스도 함께 종료하며, 아직 시작하지 않은 항목은 "취소됨"이 됩니다. |

### 기록 확인과 수정

기록하기 전에 Artist, Title, Album을 보여주고 다음 중 하나를 고르게 합니다.

- **예**: 보여준 값 그대로 기록합니다.
- **아니요**: Artist와 Title을 고칠 수 있는 입력창이 열립니다. 입력창에는 현재 값이 채워져 있습니다. 고친 뒤에는 다시 확인합니다. Album은 파일명에서 만든 값이라 고치지 않습니다.
- **기록 안 함**: 메타데이터를 기록하지 않습니다. 다운로드한 M4A와 썸네일은 그대로 남습니다.

### 기타

- 같은 이름의 파일이 있으면 덮어쓸지 묻습니다. 기본값은 **유지(건너뜀)**입니다.
- Artist/Title을 파일명에서 나눌 수 없으면 입력창이 뜹니다. 둘 다 비우면 Album만 기록합니다.
- 저장 위치 기본값은 `~/Downloads/yt-music`입니다. **폴더 선택**으로 바꿀 수 있고, 바꾼 위치는 다음 실행에도 유지됩니다.
- **완료 후 썸네일·백업 파일 삭제** 체크박스는 기본으로 켜져 있습니다. 설정은 다음 실행에도 유지됩니다. 정리 규칙은 [완료 후 정리](#완료-후-정리)를 참고하세요.
- 목록 항목을 고르면 상세 패널에 Finder에서 보기 버튼이 나타납니다.

## CLI 사용법

```bash
cd "$HOME/Downloads/yt-music"
python3 /path/to/music-manager/music_manager.py
```

`music_manager.py`는 어느 위치에서 실행해도 되며, 결과물은 기본적으로 `~/Downloads/yt-music`에 저장됩니다.

```text
YouTube URL (빈 입력 시 종료): https://www.youtube.com/watch?v=...
[1/6] 파일명 확인 중…
[2/6] 다운로드 중 (오디오 M4A + 썸네일, 시간이 걸릴 수 있습니다)…
[3/6] 썸네일 JPEG 확인…
[4/6] 메타데이터 판단 및 미리보기…
  [미리보기]
    파일     : 아이유(IU) - 밤편지.m4a
    Artist   : 아이유(IU)
    Title    : 밤편지
    Album    : 아이유(IU) - 밤편지
    CoverArt : 아이유(IU) - 밤편지.jpg
  이대로 진행할까요? [Y=기록 / n=아니요(수정) / s=건너뛰기]
[5/6] 메타데이터 기록 및 앨범 아트 삽입…
[6/6] 결과 검증…
  중간 파일 정리: 아이유(IU) - 밤편지.jpg, 아이유(IU) - 밤편지.m4a_original
  => 성공: 아이유(IU) - 밤편지.m4a

YouTube URL (빈 입력 시 종료):

=== 처리 결과 ===
[성공] #1 아이유(IU) - 밤편지.m4a
```

빈 입력을 주면 종료되고, 그동안 처리한 곡의 결과 요약이 출력됩니다.

### 확인 단계 입력

| 입력 | 동작 |
|---|---|
| Enter 또는 `y` | 보여준 값으로 기록합니다. |
| `n` | Artist와 Title을 다시 입력합니다. 입력창에 현재 값이 표시되며, Enter만 누르면 현재 값을 유지합니다. |
| `s` | 기록하지 않고 건너뜁니다. 다운로드한 파일은 그대로 남습니다. |

Artist 또는 Title을 지우려면 `-`를 입력합니다. 해당 항목은 기록하지 않습니다.

### 옵션

| 옵션 | 설명 |
|---|---|
| `--out-dir DIR` | 저장 디렉터리 지정 (기본: `~/Downloads/yt-music`) |
| `--dry-run` | 다운로드·기록 없이 예상 파일명과 Artist/Title/Album 판단 결과만 출력 |
| `--keep-intermediates` | 완료 후 썸네일과 ExifTool 백업을 지우지 않음 |

## 파일명 규칙과 메타데이터

- 결과 파일: `<제목>.m4a`와 `<제목>.jpg`입니다. 두 파일의 기본 이름은 항상 같습니다.
- 기록 항목은 `Artist`, `Title`, `Album` 세 가지뿐입니다. `Genre`는 기록하지 않습니다.
- `Album`은 실제 M4A 파일명에서 `.m4a`만 제거한 문자열입니다. 검색이나 추측을 하지 않습니다.
- `Artist`와 `Title`은 다음 순서로 자동 판단합니다.
  1. **커버 형식** `곡 제목 / 커버 아티스트 COVER` (파일명에서는 `/`가 `⧸`로 저장됨)
     - Artist = 마지막 `/` 뒤의 커버 아티스트 (`COVER` 제외)
     - Title = 마지막 `/` 앞부분에서 첫 ` - ` 앞까지, `[..]`·`『..』` 설명 블록 제거
     - 예: `One Last Kiss - 『…』 ⧸ 하나코 나나 COVER` → Artist `하나코 나나`, Title `One Last Kiss`
     - 예: `희극 (Comedy) [喜劇 / 호시노 겐] / 하나코 나나 COVER` → Artist `하나코 나나`, Title `희극 (Comedy)`
  2. **아티스트 - 제목** 형식: ` - `가 정확히 하나 있으면 나눕니다. 예: `아이유(IU) - 밤편지`
- 위 규칙으로 판단할 수 없으면 Artist와 Title을 직접 입력받습니다. 둘 다 비우면 Album만 기록합니다.
- 제목은 yt-dlp가 만드는 이름을 그대로 씁니다. 영상 제목에 `(Official Video)` 같은 문구가 있으면 Title에도 포함됩니다. 확인 단계에서 고칠 수 있습니다.

## 완료 후 정리

검증이 통과한 뒤에만 중간 파일을 지웁니다. 실패, 취소, 건너뜀이면 아무것도 지우지 않습니다.

| 구분 | 처리 |
|---|---|
| 완성된 `<제목>.m4a` | 남깁니다. |
| 이번 작업에서 새로 만든 `.jpg` / `.webp` / `.png` 썸네일 | 지웁니다. 앨범 아트는 이미 M4A에 들어 있습니다. |
| ExifTool이 만든 `<제목>.m4a_original` 백업 | 지웁니다. |
| 작업 전부터 폴더에 있던 파일 | 지우지 않습니다. |
| 덮어쓰기로 새로 받은 썸네일 | 이번 작업의 산출물이므로 지웁니다. |

- 삭제는 휴지통을 거치지 않고 바로 삭제하므로 되돌릴 수 없습니다.
- GUI는 체크박스로, CLI는 `--keep-intermediates`로 끌 수 있습니다.

## 동작 세부사항

- 다운로드는 `bestaudio[ext=m4a]/bestaudio` 포맷을 우선 선택하므로, M4A 원본이 있으면 재인코딩 없이 저장됩니다.
- 재생목록 URL이 들어와도 한 영상만 처리하도록 `--no-playlist`를 사용합니다.
- 같은 이름의 `.m4a` 또는 `.jpg`가 이미 있으면 덮어쓸지 묻고, 기본값은 **유지(건너뜀)**입니다. 덮어쓰기를 선택하면 기존 파일이 교체됩니다.
- 프로그램은 기존 음원 파일을 삭제하지 않습니다. 삭제는 위의 [완료 후 정리](#완료-후-정리) 규칙에 따른 중간 파일에만 적용됩니다.
- 한 곡이 실패해도 다음 URL 처리는 계속됩니다. 마지막에 곡별 결과를 요약합니다.
- 확인 단계에서 기록하지 않기를 고르면 다운로드한 파일은 그대로 둡니다.

## 검증 항목

기록 후 ExifTool로 다시 읽어 아래를 확인합니다. 하나라도 어긋나면 성공으로 표시하지 않고 원인을 출력합니다.

1. `Artist`가 판단하거나 입력한 값과 같은지 (값이 있는 경우에만)
2. `Title`이 판단하거나 입력한 값과 같은지 (값이 있는 경우에만)
3. `Album`이 파일명에서 `.m4a`만 뗀 문자열과 같은지
4. 앨범 아트가 삽입되었고, 내용이 JPEG 파일과 바이트 단위로 같은지

## 앱 빌드와 배포

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
./build/build_app.sh      # dist/Music Manager.app 생성
./build/build_dmg.sh      # dist/Music Manager.dmg 생성 (선택)
```

- 도구 탐색만 확인하려면 `dist/Music Manager.app/Contents/MacOS/Music Manager --selftest`를 실행합니다.
- 빌드는 개발용 ad-hoc 서명입니다. 다른 Mac에 배포하려면 Developer ID 서명과 공증이 필요합니다.
- 공증이 없으면 다른 Mac에서 처음 실행할 때 "확인되지 않은 개발자" 경고가 뜹니다. 시스템 설정 → 개인정보 보호 및 보안에서 열기를 허용해야 합니다.
- yt-dlp, FFmpeg, ExifTool은 앱에 포함되지 않습니다. 앱은 Homebrew와 Python 설치 경로에서 찾습니다. Finder로 실행하면 터미널의 PATH를 물려받지 않으므로 이 탐색이 필요합니다.

## 개발자 안내

### 테스트

```bash
.venv/bin/python -m pytest -q tests
```

- 테스트는 임시 폴더에서만 실행하며, 실제 음원 파일이나 `~/Downloads/yt-music`을 건드리지 않습니다.
- 유튜브 네트워크 요청은 가짜 yt-dlp 스크립트로 대체합니다. 실제 다운로드는 테스트에 포함하지 않습니다.
- ffmpeg와 exiftool이 없으면 해당 테스트는 건너뜁니다.

```text
music-manager/

│   ├── naming.py         파일명에서 Artist/Title/Album 판단
│   ├── tools.py          yt-dlp, ffmpeg, exiftool 경로 탐색
│   ├── runner.py         외부 명령 실행, 줄 단위 출력, 취소

│   ├── cleanup.py        완료 후 중간 파일 정리

├── build/                앱·DMG 빌드 스크립트

```

## 오류 해결

| 증상 | 원인 / 해결 |
|---|---|
| `다음 도구가 설치되어 있지 않습니다` | 표시된 설치 명령을 실행하세요. 앱에서는 시작 버튼이 비활성화되고 화면 위에 안내가 표시됩니다. |
| `yt-dlp 실패 ...` (URL 단계) | URL이 잘못되었거나 영상이 비공개/삭제되었거나 네트워크 문제입니다. yt-dlp를 최신으로 업데이트해 보세요: `python3 -m pip install -U "yt-dlp[default]"` |
| `썸네일을 찾을 수 없습니다` | 해당 영상에 썸네일이 없거나 썸네일 다운로드가 실패했습니다. M4A는 남아 있으니 수동으로 JPEG를 준비한 뒤 태그를 기록하세요. |
| `JPEG 형식이 아닙니다` | 썸네일 변환 결과가 잘못되었습니다. 해당 JPEG를 확인하거나 삭제 후 재시도하세요. |
| `같은 이름의 파일이 이미 있습니다` | 기존 파일을 옮기거나 이름을 바꾼 뒤 다시 실행하거나, 덮어쓰기를 선택하세요. |
| `구분자(' - ')가 하나가 아니어서 자동 분리할 수 없습니다` | 정상 동작입니다. 질문에 Artist와 Title을 직접 입력하세요. 둘 다 비우면 Album만 기록됩니다. |
| `검증 실패 ...` | 메타데이터 기록이 실패했거나 값이 다릅니다. 해당 M4A에 `exiftool -Artist -Title -Album -CoverArt <파일>`로 직접 확인하세요. |
| 실패·취소된 항목을 다시 시작하고 싶음 | GUI에서 항목을 고른 뒤 **선택 다시 시작**을 누르세요. |
| 한글 파일명 깨짐 | 터미널 인코딩을 UTF-8로 설정하세요. |
